# 跨境合规结论互认凭证

让境内外机构以可验证的最小凭证互认汇款前合规结论：原始档案不出机构，跨境链路只交换伪名、摘要与签名，付款门禁在任何不确定情形下一律阻断。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括境内金融机构、境外金融机构、进出口企业、合规负责人、合规审计人员。

资料所依据的领域事实如下：

- 跨境资金汇入前由境内外机构同步完成反洗钱筛查
- 审核还包括跨境合规与贸易背景核验
- 核验通过后可实现链上钱包点对点实时到账
- 机构对客户与订单使用可轮换的成对伪名标识，原始档案不出本机构
- 合规结论以数字凭证表达，包含审核范围、规则版本、证据摘要、有效期与限制条件
- 接收方可验签、质疑并要求补充核验，付款前名单更新、凭证吊销、订单变更、时区差异、重复请求与离线恢复必须得出一致结果
- 跨机构链路只交换最小证明，合规负责人可暂停互认关系，审计可还原放行或阻断原因且不泄露无关信息

## 参考实现

- `src/identifiers.js`：可轮换的成对伪名标识
- `src/credential.js`：凭证构建、签名与验签
- `src/service.js`：互认服务（签发、验签、质疑、吊销、暂停、同步、付款门禁、审计）
- `src/restrictions.js`：限制条件评估
- `src/time.js`：UTC 时间归一
- `src/crypto.js`：规范化序列化、摘要与 ed25519 签名
- `contracts/`：领域资料、凭证与事件的共享契约
- `docs/design.md`：完整设计说明

## 本地校验

运行 `npm test` 即可检查领域资料读取与互认服务的全部一致性场景（名单更新、凭证吊销、订单变更、时区差异、重复请求、离线恢复、互认暂停、质疑核验、最小披露）。仓库不保存账号、密钥、连接串或真实身份信息。
