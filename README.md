# 跨境合规结论互认凭证

让境内外机构以可验证的最小凭证互认汇款前的反洗钱、贸易背景与跨境合规审核结论：
完整客户档案永不离开本机构，跨境链路只交换签名凭证与最小证据摘要，
接收方可验签、质疑、要求补充核验；名单更新、凭证吊销、订单变更、
时区差异、重复请求与机构离线恢复都必须在付款前得出一致结果。

## 设计原则

- **数据最小化**：链路只出现可轮换假名、订单指纹、证据摘要与限制条件；原始材料留在签发机构。
- **fail closed**：签名、受众、有效期、订单绑定、流新鲜度等任何一项无法确认，一律阻断。
- **确定性一致**：付款判定是纯函数 `(凭证, 折叠状态, UTC 时刻)`；事件按 `(ts, iss, seq)` 全序折叠，到达顺序不影响结论。
- **可审计**：每笔付款产出签名决策回执，审计只汇总与该笔相关的凭证与事件，不泄露无关交易信息。
- **合规主权**：合规负责人可对任一互认关系立即暂停，暂停事件沿签名流传播。

## 模块

| 文件 | 职责 |
| --- | --- |
| `src/lib/encoding.js` | base64url、确定性 JSON（键排序）、SHA-256 |
| `src/lib/envelope.js` | Ed25519 数字信封 `v1.<负载>.<签名>`，按 `kid` 选验签钥 |
| `src/lib/identity.js` | 可轮换假名（按机构对+轮换周期 HMAC 派生）、订单指纹、随机数 |
| `src/lib/attestation.js` | 合规凭证：审核范围、规则版本、证据摘要、有效期、限制条件 |
| `src/lib/keyring.js` | 机构 Ed25519 密钥环，支持轮换与旧钥保留 |
| `src/lib/stream.js` | 哈希链签名事件流（本地只增流 + 复制日志），验签/查缺/去重/断链拒绝 |
| `src/lib/state.js` | 事件状态折叠与纯函数付款门禁 |
| `src/lib/node.js` | 机构节点：签发、验签、质疑、补充、吊销、暂停、付款、审计 |

## 凭证与事件

凭证（`compliance-credential/v1`）包含：签发方与受众、主体假名、订单指纹、
审核范围 `aml / trade / crossborder`、各范围规则版本、证据摘要数组、
`iat/nbf/exp`（UTC 纪元秒）、限制条件、父凭证（换发链）与 `kid`。

事件流每机构一条，哈希链相扣，事件类型：

- `sanction.list.updated`：名单条目增量（added / removed，带名单版本）
- `rule.floor.updated`：各审核范围最低规则版本（跨机构取最高值）
- `credential.revoked`：凭证吊销
- `relationship.suspended` / `relationship.resumed`：互认暂停与恢复
- `key.rotated`：验签钥轮换公告（由**旧钥**签名，形成轮换锚链）

## 付款前如何达成一致

1. 接收方验签凭证并校验受众、有效期、审核范围完整性、订单指纹绑定。
2. 付款请求必须附带签发方新鲜的 **流头检查点**（`stream-head/v1`，含末端序号与哈希）。
   - 拿不到流头（签发方离线）→ `stream_head_missing`，阻断；
   - 本地水位落后于流头（恢复未完成）→ `stream_behind`，阻断；
   - 流头过期 → `stream_head_stale`，阻断。
3. 在已追平的状态上检查：名单命中、凭证吊销、互认暂停、规则底线、限制条件、本地复核。
4. 判定按幂等键缓存；重复请求（重试、时区边界重放）返回首次结论，一次性凭证只放行一次。
5. 决策回执（`payment-decision/v1`）由接收方签名，含全部阻断原因、规则版本与各流水位。

**时区**：所有时间字段为 UTC 纪元秒，同一瞬间各地 epoch 相同，不因 UTC+8 / UTC+1 产生分歧。
**离线恢复**：按 `(issuer, seq)` 水位只补发缺口；重复信封幂等跳过，跳号/断链/伪签整体拒绝。

## 质疑与补充核验

接收方可就凭证发起 `compliance-challenge/v1`（限定具体审核范围与问题）；
签发方只返回被质疑范围的证据摘要与显式点名的字段（`compliance-supplement/v1`），
超出凭证范围的质疑与补充都会被拒绝。原始客户档案始终不出境。

## 审计

`auditReport(幂等键)` 返回签名回执、放行/阻断的中文解释、仅与该笔相关的脱敏事件与补充证明。
名单事件只保留该笔主体假名的条目；其他交易的假名、条目与客户信息不会出现。
